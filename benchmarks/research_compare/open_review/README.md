# Exploratory diagnostic and code-review follow-up

This is a separate, two-case exploratory corpus motivated by coverage of natural review tasks. It does not revise the original frozen fact-question study or its outcomes. These fixtures contain deliberate benchmark-owned seeded mutations; findings are not allegations of defects in upstream projects. The original MCP skill remains the MCP-arm instruction; there is no bare-MCP arm.

Each `cases/<case>/workspace` is the complete worker-visible input for both arms. It contains only RTL, headers/licenses/manifests, task text and normalized compile configuration. The public configuration is `config.json`, with `top_module`, `include_directories`, `defines`, and `single_unit` matching the original skill. Paths in configuration are relative to the workspace root, including the `rtl/` prefix. No oracle, patch, provenance report or validation result belongs in a worker workspace. Both arms must receive identical workspace bytes and read-only access. Source ordering remains the worker's choice.

Each task asks for a prose review against a small explicit integration contract, including source behavior that compilation alone cannot settle. It does not disclose a target finding count, categories, or fault locations. Each integration also instantiates one explicitly unavailable, monitor-only external module; do not invent its implementation. Missing-monitor diagnostics are boundary evidence, not another seeded local issue.

The independent source-derived `oracle.md`, individual mutation patches, original hashes and resulting hashes live outside worker workspaces. The source-derived oracles and mutation records were prepared before compiler corroboration. A subsequent independent pre-freeze review clarified IDMA flush wording and normalized public configuration names to match the unchanged original skill; this task/config-only revision is recorded in provenance. Sources, oracle facts and effective compiler settings remain unchanged, and no follow-up workloads have started. Compiler validation is corroboration of the seeded compile effects, not the answer key or grading method. Accept equivalent technically correct prose and source/hierarchy references, rather than requiring particular diagnostics or JSON strings.

`materialize.sh` copies only worker inputs to `/private/tmp/slang-compare-open/inputs/<case>` and makes them read-only. It refuses existing destinations. Controller-only manifest, protocol, frozen identity and workload records are separate and are not part of these workspaces. No additional cases may be selected after observing follow-up outcomes.
