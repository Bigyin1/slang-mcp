1. `DEPTH=8` and effective `ADDR_DEPTH=3` (`$clog2(8)`) from L20/L24. Both counters are declared as packed `logic [ADDR_DEPTH:0]` at L50, resolving to four-state, unsigned `logic [3:0]`, width 4.

2. All `status_cnt_q` source-level reads:

| Context | Reads |
|---|---|
| Continuous assignments | L63: low-bit slice for `usage_o`; L69: full comparison; L70: empty comparison |
| `always_comb read_write_comb` | L79 default next state; L116 increment RHS; L127 decrement RHS; L131 simultaneous-operation hold; L134 zero test in optional branch; L142 optional-branch hold |
| `always_ff` / assertions | No direct reads |

3. `status_cnt_q` has exactly three writes, all nonblocking in the sequential block: async active-low reset to zero (L155–158), then flush-to-zero priority (L162–165), otherwise capture `status_cnt_n` (L168–171). Thus priority is reset > flush > combinational next state.

4. `status_cnt_n` is a staged next-state value, not an in-place RMW variable.

- Its only read is L171, when `status_cnt_q <= status_cnt_n`.
- Its writes are blocking assignments in `read_write_comb`: default from `q` (L79), `q + 1` (L116), `q - 1` (L127), hold at simultaneous accepted operations (L131), and hold in the optional fall-through/Altera path (L142).
- No RHS reads `status_cnt_n`; every arithmetic/hold assignment derives from `status_cnt_q`. Later source-order assignments override earlier staged values.

5. Let `C` be a normal pre-clock occupancy in `0..8`, with reset deasserted and no flush. At defaults, `full_o = (C == 8)` and `empty_o = (C == 0)` (L69–70).

| Inputs | Acceptance guard | Resulting staged count |
|---|---|---|
| Push only | `push_i && ~full_o` (L99) | `C+1` for `C=0..7`; unchanged at `C=8` |
| Pop only | `pop_i && ~empty_o` (L119) | `C-1` for `C=1..8`; unchanged at `C=0` |
| Neither | Neither guarded block runs | Remains `C` via L79 |

Accepted pushes/pops also advance their respective pointers (L112–114, L124–125).

6. With both raw inputs high:

| Occupancy | Guarded source behavior | Final `status_cnt_n` |
|---|---|---|
| 0 | Push accepted; pop blocked by `empty_o`; simultaneous-hold condition is false | 1 |
| 1–7 | Both blocks run, then L131 overrides their interim values with `status_cnt_q` | unchanged |
| 8 | Push blocked by `full_o`; pop accepted; simultaneous-hold condition is false | 7 |

The source assertions at L222–228 additionally require no raw push while full and no raw pop while empty. Therefore, assuming reset is not disabling them, simultaneous push/pop at occupancy 0 conflicts with `empty_read`, and at occupancy 8 conflicts with `full_write`, even though the guards produce the count behavior above. They are written inside the `translate_off` region (L216–229).

7. The procedural fall-through/Altera branch at L134 is syntactically present. It reads `status_cnt_q` at L134 and L142 and writes `status_cnt_n` at L142. Under defaults, `FALL_THROUGH=0`, `FPGA_EN=0`, and `FPGA_ALTERA=0`, making its first condition false; its body cannot select an update. Slang’s elaborated hierarchy correspondingly contains `gen_fifo` and `gen_asic_queue`, not the FPGA generate path. The ordinary counter updates remain possible; the branch-specific L142 hold does not.

8. The width difference is intentional but significant:

- The internal counter needs 4 bits to represent full occupancy eight: `4'b1000`.
- `usage_o` is only 3 bits and explicitly receives `status_cnt_q[2:0]` (L63), so at full it is `3'b000`.
- `full_o` avoids that truncation: it compares the full 4-bit counter against `FifoDepth[3:0]`, which is `4'b1000` for depth 8 (L43, L69).

Thus `usage_o==0` alone does not distinguish empty from full; `full_o` carries that distinction.
